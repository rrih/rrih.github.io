# Rust migration verification

Application UI, routing, keyboard and touch navigation, metadata validation, persistence, translations selection, image states, and PWA messaging now run in Rust / Yew WebAssembly. All seven locale dictionaries were compared to the previous application and match exactly; CSS and icon assets are unchanged.

Application and service-worker behavior are Rust. The authored production JavaScript is limited to the module bootstrap and a small service-worker event/boot adapter; wasm-bindgen generates the browser ABI. Browser service-worker events require synchronous `respondWith` / `waitUntil` wiring. Cache policies, image allowlisting, TTL, LRU pruning, settings, message handling, and response selection live in `worker/src/`. The adapter reads its version-matched WASM from the shell cache when restarting offline. The Rust xtask builds both modules and the shell manifest, precaches both WASM modules and their bindings, and serves previews. Each complete generated JS/WASM package has a content-addressed directory, and the app bootstrap also has a content-addressed URL. A worker activated during another page's initialization can serve that page's original immutable module from the retained Pictulane shell. User routes, the worker URL and scope, `pictulane:v1:*` storage, and `pictulane-images-v1` / `pictulane-image-meta-v1` are unchanged.

## Content-addressed runtime verification

Five additional Playwright scenarios use a real local HTTP server without route interception. They derive incompatible ABI generations from the actual generated modules by changing one WASM export name and its matching JS reference. One keeps the first generation in the HTTP cache while an uncontrolled page loads the next release. Four pause after the old JS loads, activate another worker from a different tab, then verify that the original WASM comes from the retained Pictulane shell even when the server no longer serves that release and an unrelated cache contains an incompatible response. A page-local promise pauses initialization without holding an unfinished service-worker fetch event; the test waits for the replacement worker to reach `activated`. The HTTP cache is then cleared before WASM loads, so a network fallback cannot mask a missing shell-cache response. These cover a direct update, failed same-shell and intermediate installations, a complete waiting worker superseded before activation, and a complete legacy shell without an activation marker. Same-shell successful and failed installations must preserve the original activation marker and exact cached HTML/WASM bytes.

Shell activation is recorded inside the existing Pictulane shell cache, so retention follows the previous active generation rather than cache creation order. Failed new installs remove only newly created caches. Reinstallation failures preserve an existing active cache. Complete legacy shells without an activation record are retained conservatively until a marked predecessor exists; empty failed shells and superseded waiting shells do not displace the active predecessor.

The existing offline-worker test checks the content-addressed WASM URL and magic bytes. Native cases cover the complete generated package fingerprint and the old-shell URL boundary. The full `npm run dev-check` passed after the final Rust change, including WASM Clippy, the seven application/worker unit tests, and production generation. ESLint and TypeScript static checks also passed after the final test synchronization changes. All 21 Playwright scenarios passed in 49.5 seconds with installed Google Chrome and the corrected native Rust preview server. The first failed run exposed an unchecked service-worker registration value when registration was blocked; the Rust code now validates that value and returns safely, matching the old TypeScript catch boundary. Diagnostic failures and their subsequent passing runs remain in separate logs.

The production build was restored and read back after the tests. Package and bootstrap hashes, every precache entry, the shell content hash, WASM magic bytes, test-fixture exclusion, and the unchanged user-owned documentation hashes passed. Its worker package is byte-identical to the tested fixture worker. Evidence, source/output hashes, the initial failures and final Playwright report are under `work/rust-migration/pictulane-content-hash-final/`. Both the dedicated browser contexts and preview server were stopped; no composition, commit, push or deployment was performed by this verification.

## Existing limitations

Shell retention remains bounded to the current and immediately preceding active generation. A page paused across multiple completed activations is not guaranteed to finish loading assets from an older release. The old JavaScript worker also retained only one previous shell and did not fall back to it when serving old asset URLs; Rust adds a distinct JS-to-WASM initialization interval. The new regression tests certify a single activation across that interval, including failed or waiting intermediate workers, rather than unlimited release retention.

Live X acquisition is still unavailable, as before. Fixture E2E is not evidence of a working live provider. Physical-device iOS/Android installation, native pinch/edge gestures, and installed-app storage sharing have not been newly device-tested. No remote push or Pages deployment is performed by this verification.
